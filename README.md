# 진짜 있는 말? — 정직한 신조어 해석기

이 앱은 모르는 신조어를 만난 사람이 AI가 지어낸 뜻에 속지 않게, **그 말이 진짜 쓰이는지부터** 확인해 줍니다. 쓰이는 말이면 뜻과 출처를, 쓰인 흔적이 없으면 AI에게 안전하게 묻는 법을 알려 줍니다.

근거 논문: 「AI는 모르는 신조어 앞에서 모른다고 말하는가 — 한국어 가짜 신조어의 형성 방식과 AI의 뜻 지어내기」(김가은, 2026)

## 실행 방법

### 1. 파일로 바로 열기 (설치·키 필요 없음)

1. ZIP 파일의 압축을 풉니다.
2. 폴더 안의 `index.html` 을 더블클릭합니다.

이 방법으로는 앱 사전(122개)·논문의 가짜 말(70개)·AI 답 점검·퀴즈가 모두 동작합니다. 사전에 없는 말의 **실제 쓰임 확인**만 "아직 모름"으로 나옵니다(서버가 필요해서).

### 2. 공개 주소로 올리기 (Vercel, 실제 쓰임 확인까지)

1. 이 폴더를 GitHub 저장소에 올리고 Vercel에서 가져옵니다(빌드 설정 없음).
2. Vercel 프로젝트의 Settings → Environment Variables 에 아래 키를 넣고 다시 배포합니다.

| 환경 변수 이름 | 어디서 받나 | 없으면 |
|---|---|---|
| `NAVER_CLIENT_ID` | 네이버 클라우드 콘솔 → NAVER API HUB → 앱 등록(검색 - 블로그, 검색 - 카페글) → Client ID | 실제 쓰임 확인을 하지 않고 "아직 모름"으로 안내 |
| `NAVER_CLIENT_SECRET` | 위와 같은 곳 → Client Secret | 위와 같음 |

네이버 개발자센터(developers.naver.com)는 2026년 7월 31일부터 검색 API 새 키를 주지 않습니다. 예전에 받은 개발자센터 키가 있다면 같은 이름으로 넣어도 됩니다(2027년 6월 30일까지 동작, 앱이 자동으로 알아봄).

키를 넣고 다시 배포한 뒤 `https://내주소/api/lookup?w=럭키비키` 를 열어 `"web":{"status":"ok"` 와 `"dict":{"status":"ok"` 가 보이면 연결된 것입니다. `"off"` 는 키가 안 들어감, `"error"` 는 키가 틀렸거나 API를 고르지 않음입니다.
| `OPENDICT_API_KEY` | 우리말샘(opendict.korean.go.kr) → 개발 지원(오픈 API) → 키 신청 | 우리말샘 뜻풀이 없이 네이버 쓰임만 확인 |

키는 `api/lookup.js` 가 서버에서만 읽습니다. 소스 파일과 화면 어디에도 키가 들어가지 않습니다.

## 해 볼 일 세 가지

| 할 일 | 해 보는 방법 | 이렇게 나오면 통과 |
|---|---|---|
| 1. 모르는 말의 뜻 찾기 | "말 찾기"에 `얼죽아` 를 넣고 "찾기" | 초록 도장 "확인된 뜻 있음"과 뜻·예문이 나옴 |
| 2. 없는 말 확인하기 | `퇴노듣` (논문에서 만든 가짜 말)을 넣고 "찾기" | 빨간 도장 "논문의 가짜 말", 만든 뜻과 "6번 중 2번 단정", **"퇴노듣"라는 말이 실제로 있어?** 질문과 ChatGPT·Claude 바로 열기 버튼이 나옴. "논문 근거 자세히 보기"를 누르면 47% / 3% 막대그래프가 나옴 |
| 3. AI 답 믿어도 될지 확인하기 | "AI 답 점검" 탭에서 "예시 답변으로 해 보기" | "확인 없이 뜻을 단정했어요"와 "논문에서 만든 가짜 말이에요"가 나오고, "어떤 표현을 보고 판단했는지 보기"를 누르면 형광펜 표시가 나옴 |

공개 주소에서는 사전에 없는 실제 신조어(예: `럭키비키`)를 넣으면 "실제로 쓰여요" 도장과 실제로 쓰인 글(원문 링크)이 나옵니다.

잘못된 입력도 시험해 보세요. 빈칸, 이모지, 숫자만, 아주 긴 글, `<script>` 같은 글을 넣어도 안내 문구만 나오고 앱은 멈추지 않습니다.

## 사전에 없는 말을 판정하는 방법

논문에서 가짜 말을 검증한 절차(부록 D)를 그대로 씁니다.

| 결과 | 기준 | 화면 |
|---|---|---|
| 사전에 있음 | 우리말샘에 표제어가 같은 말이 있음 | 우리말샘 뜻풀이와 링크 |
| 실제로 쓰여요 | 네이버 블로그·카페를 따옴표로 검색해, 제목이나 본문 요약에 그 말이 그대로 든 글이 5건 이상 | 실제로 쓰인 글 3개와 원문 링크. 앱은 뜻을 지어내지 않음 |
| 드물게 쓰여요 | 1~4건 | 쓰인 글 + AI에게 묻는 법 + 논문 수치 |
| 쓰인 흔적 없음 | 0건 (블로그·카페·우리말샘을 모두 확인한 경우만) | AI에게 묻는 법 + 논문 수치. "없는 단어라는 증명은 아님" |
| 추가 확인 필요 | 1~4건이거나, 자료 일부(블로그·카페 중 한쪽, 또는 우리말샘)를 확인하지 못한 경우 | 확인하지 못한 자료와 다시 시도 |
| 검색 실패 | 서버·인터넷 연결 실패 | "결과가 없다는 뜻이 아님" + 다시 시도 |
| 논문의 가짜 말 | 논문 연구 1·2의 가짜 말 70개 | 만든 뜻, AI가 단정한 횟수(논문 부록 D) |

모든 결과에는 **상태 문구**(색과 함께 글자로), **확인 근거**(사전 확인 · 온라인 사례 수 · 출처 · 확인일 · 범위와 한계), **결과 복사 · 다시 검색 · 결과 지우기 · 출처 바로가기** 버튼이 붙습니다. 외부 링크는 서버가 실제로 돌려준 주소만 보여 줍니다.

## 논문 결과를 어떻게 쓰는가

- **질문 방식**: 가짜 줄임말을 "무슨 뜻이야?"로 물으면 AI가 47%를 단정했고, "실제로 있어?"로 물으면 3%였습니다(연구 1·2 합산). 그래서 논문에서 시험한 질문 **"○○라는 말이 실제로 있어?"** 를 그대로 만들어 줍니다. 따옴표는 낱말이 조사와 붙어 읽히는 문제(논문 한계 6)를 막으려고 앱이 더했습니다. "확실하지 않으면 모른다고 답해 줘"는 논문에서 시험하지 않은 문장이라 사용자가 고를 때만 붙입니다.
- **말의 생김새**: 줄임말처럼 생긴 가짜 말(25%)이 낯선 글자가 섞인 가짜 말(3.3%)보다 더 자주 단정되었습니다. 쓰인 흔적이 없는 한글 세 글자 말에만 그 유형의 논문 수치를 보여 줍니다(논문이 세 글자 말만 시험했으므로).
- **응답 분류 기준(A~E)**: 논문이 AI 답을 나눈 다섯 범주를 표현 규칙으로 옮겨 "AI 답 점검"에 썼습니다. 애매하면 사용자를 안심시키는 쪽이 아니라 조심하게 하는 쪽으로 판정합니다.
- **퀴즈**: 논문 연구 1의 가짜 말 30개와 실제 신조어 대조군 20개를 섞어 냅니다.

모든 수치는 `logic.js` 의 `PAPER` 한곳에 있고, 화면은 모두 여기서 숫자를 가져옵니다.

## AI 답 점검을 논문 응답으로 채점하기

논문 재현 패키지의 분류 결과로 앱 판정이 연구자 분류와 얼마나 같은지 잴 수 있습니다.

```
cd source
node score_checker.js <연구1 classified.csv 경로> <연구2 분류 파일 경로>
```

일치율과 혼동표가 출력되고 `checker_score.js` 가 만들어져, "AI 답 점검" 화면에 일치율이 표시됩니다. 열 이름을 못 찾으면 열 목록을 보여 주니 `--text 응답열 --code 연구자코드열 --word 단어열` 로 지정합니다.

## 데이터와 개인정보

- 사전의 말 가운데 "우리말샘 등재 확인" 표시가 있는 20개는 논문 대조군으로 국립국어원 우리말샘 등재를 확인한 말입니다. 나머지 뜻과 예문은 앱 제작자가 직접 쓴 글입니다.
- 실제 개인정보는 들어 있지 않습니다. 예문은 모두 지어낸 예시입니다.
- 서버로 보내는 것은 찾은 낱말 하나뿐이며, 실제 쓰임 확인에만 씁니다. 앱 코드는 낱말을 따로 저장하지 않습니다(Vercel의 기본 접속 기록에는 요청 주소가 남을 수 있습니다). AI 답 점검에 붙여 넣은 글은 어디에도 보내지 않습니다.
- 찾은 말 목록(최대 8개)만 그 기기의 브라우저에 남습니다.
- 비밀값은 환경 변수(`NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `OPENDICT_API_KEY`)로만 읽습니다.

## 한계

- 흔적을 찾지 못했다는 것은 "아직 확인하지 못했다"는 뜻이지 "없는 말"이라는 판정이 아닙니다. 네이버 블로그·카페 밖(다른 SNS, 비공개 공간)에서만 쓰이는 말은 찾지 못합니다.
- 글에 같은 글자가 있어도 사람 이름·가게 이름처럼 다른 뜻일 수 있어, 쓰인 글을 직접 열어 보도록 안내합니다.
- 생김새 판정과 답변 점검은 규칙에 따른 자동 판단이라 사람이 읽는 것만큼 정확하지 않습니다.
- 논문 수치는 각 회사 API로 물은 결과라, 웹 검색이 켜진 채팅 앱의 답과는 다를 수 있습니다.

## 공개 주소를 만든 뒤 할 일

1. 카카오톡 미리보기 그림이 보이려면 `index.html` 의 `<meta property="og:image" content="og.png">` 에서 `og.png` 를 전체 주소로 바꿉니다. 예: `https://jinjja-app.vercel.app/og.png`
2. "빠진 말 알려 주기"를 쓰려면 `config.js` 의 `reportUrl` 에 구글 폼 주소를 넣습니다(폼에 이름·연락처 칸은 두지 않기).
3. 화면 파일을 고쳐 다시 배포할 때는 `sw.js` 의 `CACHE` 이름 숫자를 올립니다.
